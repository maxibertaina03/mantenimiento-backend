DIAGRAMA DE DEPENDENCIAS
========================

┌─────────────────────────────────────────┐
│         PRESENTATION LAYER              │
│  (Controllers, DTOs, Middlewares)       │
└──────────────────┬──────────────────────┘
                   │ Depends on
                   ▼
┌─────────────────────────────────────────┐
│        APPLICATION LAYER                │
│  (Use Cases, App Services, Mappers)     │
└──────────────────┬──────────────────────┘
                   │ Depends on
                   ▼
┌─────────────────────────────────────────┐
│           DOMAIN LAYER                  │
│  (Entities, Value Objects, Services)    │
└──────────────────┬──────────────────────┘
                   │ Depends on (via interfaces)
                   ▼
┌─────────────────────────────────────────┐
│       INFRASTRUCTURE LAYER              │
│  (Repository Implementations, DB)       │
└─────────────────────────────────────────┘

NOTAS IMPORTANTES
=================

✅ DOMAIN: NO depende de nada (standalone)
✅ APPLICATION: Solo depende de DOMAIN
✅ INFRASTRUCTURE: Implementa interfaces de DOMAIN
✅ PRESENTATION: Orquesta APPLICATION

❌ Nunca importar desde presentation a infrastructure
❌ Nunca importar servicios de otro módulo directamente
❌ Siempre usar interfaces (contratos) del domain

NOMENCLATURA
============

Entities:       {Nombre}.entity.ts
Value Objects:  {Nombre}.vo.ts
Repositories:   {Nombre}.repository.ts (interfaz)
                prisma-{Nombre}.repository.ts (impl)
Services:       {Nombre}-{layer}.service.ts
Use Cases:      {action}-{entity}.use-case.ts
DTOs:           {entity}-{type}.dto.ts (request/response/input/output)
Mappers:        {entity}.mapper.ts
Middlewares:    {entity}-{function}.middleware.ts
Controllers:    {entities}.controller.ts
Exceptions:     {domain}-error.exception.ts o {specific}.exception.ts
